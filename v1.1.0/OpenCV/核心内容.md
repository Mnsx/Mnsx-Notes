# 核心内容

## Mat

### 数据结构

Mat基本上是一个包含两部分数据的类

1. **矩阵头**：包含矩阵尺寸、存储方法、存储地址等信息，其大小是恒定的
2. **指向像素矩阵的指针**：包含实际的像素值，其大小随图像不同而变化

采用**引用计数系统**来进行传输，解决拷贝的消耗问题，其核心思想是：每个Mat对象都有自己的头信息，但多个Mat对象可以通过让它们的指针指向同一个内存地址来共享一个矩阵，**拷贝运算符只会复制矩阵头和指针**，而不会复制原始像素数据

```c++
cv::Mat a, c;
a = cv::imread("static/flower.jpg", cv::IMREAD_COLOR);

cv::Mat b(a); // 通过拷贝构造实现，实际上是指向同一个数据
c = a; // 通过拷贝赋值运算符实现，实际上指向同一个数据
```

可以通过ROI创建只引用完整数据中某个子集的矩阵头，ROI的实现原理可以理解为**零拷贝**

1. 计算新矩阵头的起始指针地址：`NetDataPtr = OldDataPtr + (y * Step + x * ElementSize)`
2. 设置新的行数和列数
3. 保持原有的Step（每一行占用的内存字节数）

如果一个矩阵本身可以属于多个Mat对象，那么**最后一个使用它的对象销毁时，会判断当前引用计数器是否为零，如果为零那么就会释放矩阵数据**

如果需要复制矩阵本身（数据），可以通过`cv::Mat::clone()`和`cv::Mat::copyTo()`函数

```c++
cv::Mat f = a.clone(); // 深拷贝，复制的数据
cv::Mat g;
a.copyTo(g); // 深拷贝，复制的数据
```

### 存储方法

可以选择不同的颜色空间和数据类型存储像素值

颜色空间指如何组合颜色分量来编码一种特定的颜色

* **RGB/BGR**：默认格式，适用于图像显示、基础绘图
* **HSV和HLS**：将颜色分解为色调、保护度和亮度，**通过忽略亮度分量，可以让算法对光照变化不那么敏感**，适用于颜色过滤、物体追踪（不受阴影/光照干扰）
* **YCrCb**：常用于JPEG图像格式
* **CIE LAB**：感知均匀的颜色空间，如果需要测试两种颜色之间的差异可以使用，适用于颜色相似度计算、高质量图像处理
* **Gray**：只有一个通道，适用于边缘检测、特征提取（减少计算量）

数据结构决定对每个分量域的控制精度

* **char（8位/1字节）**：最轻量，无符号或有符号
* **float（32位）或double（64位）**：提供更精确的控制，但是会大幅增加内存占用

> **数据类型与内存计算**
>
> ```c++
> Memory Size = Width * Height * CHannels * sizeof(DataType)
> ```
>
> 使用char数据结构和RGB颜色空间的1080p图像大致等于`1920 * 1080 * 3 * 1 = 6.2MB`

### 创建Mat对象

> `cv::write()`函数可以将矩阵写入图像文件，使用左移运算符也能使用相同的效果，但是只能适用于二维矩阵
>
> ```c++
> cout << "R (c)       = " << endl << cv::format(l, cv::Formatter::FMT_C) << endl << endl;
> ```

* **使用构造函数**：定义行列数、数据类型和通道数，并使用`cv::Scalar`初始化所有像素点

  ```c++
  cv::Mat l = cv::Mat(4, 4, CV_8UC4, cv::Scalar(0, 2, 3, 0));
  ```

* **使用C++数组初始化**：适用于创建超过二维的多维数组，通过传递维度数组来指定各维度大小

  ```c++
  int sz[3] = {2, 2, 3};
  cv::Mat l(3, sz, CV_8UC(1), cv::Scalar::all(0));
  ```

* **`cv::Mat::create`函数**：只有新尺寸和旧尺寸不匹配时才会重新分配内存，不能初始化数值

  ```c++
  l.create(4, 4, CV_8UC(2));
  ```

* **MATLAB风格初始化**：提供zeros、ones和eye等方法

* **逗号分隔符或初始化列表**：适用创建小型矩阵（如卷积核）

  ```c++
  cv::Mat l = (cv::Mat_<double>(3, 3) << 0, -1, 0, -1, 5, -1, 0, -1, 0);
  ```

* **克隆或拷贝**：为现有矩阵创建新的头部，并使用clone或cloneTo进行深拷贝

* **随机初始化**：使用randu函数填充随机数，需指定上下限

> **OpenCV数据类型宏**
>
> `CV_[位数][有无符号][前缀]C[通道数]`
>
> CV_8UC3表示8位无符号字符型三通道

## 图像扫描

### 查找表

查找表（Lookup Table）是一个预先计算好的值映射表，对于8位图像，它是一个只有256个元素的数组

* **性能**：如果交换逻辑涉及复杂的数学运算，对几百万像素重复计算极其低效，使用LUT复杂度就会从O(N)的复杂运算降低到O(N)的内存访问
* **指令优化**：OpenCV的`cv::LUT`函数内使用SIMD指令集，比代码实现的循环快得多

### 时间测量

* `cv::getTickCount()`：获取CPU刻度
* `cv::getTickFrequency()`：获取每秒刻度数

```c++
Time(sec) = (EndTick - StartTick) / Frequency
```

### 内存布局

矩阵大大小取决于颜色系统，也就是通道数

通道顺序是反向的，BGR而不是RGB

在许多情况下，内存足够大，可以连续存储每一行，使得行与行之间首尾相接，形成一个长单行，这会使得由于所有数据都按顺序排列在同一个地方，有助于加快扫描速度，**可以通过使用`cv::Mat::isContinuous()`函数判断矩阵是否连续存储**

OpenCV内存主要采用**交织存储**，及`B1 G1 R1 | B2 G2 R2`

### 图像扫描方法对比

* **通过数组遍历**

  ```c++
  cv::Mat& scanImageAndReduce(cv::Mat& image, const uchar* const table) {
      CV_Assert(image.depth() == CV_8U); // 只接受uchar的矩阵
  
      int channels = image.channels();
  
      int rows = image.rows;
      int cols = image.cols;
  
      // 判断内存是否连续
      if (image.isContinuous() == true) {
          cols *= rows;
          rows = 1;
      }
  
      for (int i = 0; i < rows; ++i) {
          auto items = image.ptr<uchar>(i);
          for (int j = 0; j < cols; ++j) {
              items[j] = table[items[j]]; // 查表并赋值
          }
      }
      
      return image;
  }
  ```

* **通过迭代器遍历**

  ```c++
  cv::Mat& scanImageAndReduceIterator(cv::Mat& image, const uchar* const table) {
      CV_Assert(image.depth() == CV_8U);
  
      const int channels = image.channels();
      switch (channels) {
          case 1: {
              cv::MatIterator_<uchar> it, end;
              for (it = image.begin<uchar>(), end = image.end<uchar>(); it != end; ++it) {
                  *it = table[*it];
                  break;
              }
          }
          case 3: {
              cv::MatIterator_<cv::Vec3b> it, end;
              for (it = image.begin<cv::Vec3b>(), end = image.end<cv::Vec3b>(); it != end; ++it) {
                  (*it)[0] = table[(*it)[0]];
                  (*it)[1] = table[(*it)[1]];
                  (*it)[2] = table[(*it)[2]];
              }
          }
      }
  
      return image;
  }
  ```

* **通过动态地址计算遍历**

  ```c++
  cv::Mat& scanImageAndReduceRandomAccess(cv::Mat& image, const uchar* const table) {
      CV_Assert(image.depth() == CV_8U);
  
      const int channels = image.channels();
  
      switch (channels) {
          case 1: {
              for (int i = 0; i < image.rows; ++i) {
                  for (int j = 0; j < image.cols; ++j) {
                      // 动态计算(i, j)的地址并返回引用
                      image.at<uchar>(i, j) = table[image.at<uchar>(i, j)];
                  }
              }
          }
          case 3: {
              // 使用Mat_模板类简化语法
              cv::Mat_<cv::Vec3b> temp_image = image;
              for (int i = 0; i < image.rows; ++i) {
                  for (int j = 0; j < image.cols; ++j) {
                      temp_image(i, j)[0] = table[temp_image(i, j)[0]];
                      temp_image(i, j)[1] = table[temp_image(i, j)[1]];
                      temp_image(i, j)[2] = table[temp_image(i, j)[2]];
                  }
              }
              image = temp_image;
              break;
          }
      }
  
      return image;
  }
  ```

| **扫描方法** | **核心写法**            | **优点**                   | **缺点**                   |
| ------------ | ----------------------- | -------------------------- | -------------------------- |
| **指针法 **  | `p = I.ptr<T>(i); p[j]` | **极致性能**，利用连续性   | 需手动处理多通道           |
| **迭代器法** | `it = begin<T>()`       | **代码优雅**，自动处理跳转 | 性能略有损耗               |
| **动态地址** | `I.at<T>(i, j)`         | **最安全**，支持随机访问   | **极慢**（不适合全图扫描） |

* **核心方法**

  OpenCV提供了专门用于修改图像值得函数，无序编写扫描逻辑，`cv::LUT()`

  ```c++
  cv::Mat& scanImageAndReduceLUT(cv::Mat& image, const cv::Mat& lookUpTable) {
      CV_Assert(image.depth() == CV_8U);
      CV_Assert(lookUpTable.total() == 256 && lookUpTable.type() == CV_8U);
  
      // 直接调用内置优化函数
      cv::LUT(image, lookUpTable, image);
  
      return image;
  }
  ```

## 图像处理

### 图像读写

* **读取**：`imread`默认创建3通道BGR图像，如果需要灰度图，需要显示指定`IMREAD_GRAYSCALE`
* **保存**：`imwrite`根据文件扩展名自动压缩
* **内存读写**：`imdecode`和`imencode`用于直接在内存Buffer中处理图像

### 像素级操作

* **访问强度**：必须指定类型和通道
  * 灰度（8UC1）：`img.at<uchar>(y, x)`
  * 彩色（BGR）：`img.at<Vec3b>(y, x)`
  * 浮点（32F）：`img.at<Vec3f>(y, x)`
* **注意顺序**：坐标始终是(y, x)，或者使用`at<uchar>(Point(x, y))`
* **向量转换**：`std::vector<Point2f>`可以直接构造Mat

### 基础算子

* **清空图像**：`img = Scalar(0)`
* **ROI**：`Mat smallImg = img(Rect(10, 10, 100, 100))`
* **类型转换**：`src.convertTo(dst, CV_32F)`，支持在转换时进行缩放和偏移

### 可视化调试

* **显示**：`imshow`后必须介绍`waitKey()`才能看到窗口
* **浮点图显示**：32F图像直接显示会变成全白或杂色，必须先映射到**8U**范围

## 线性变换

### 数学模型

```shell
g(i, j) = a * f(i, j) + b
```

* `f(i, j)`：原始像素值
* `g(i, j)`：变换后的像素值
* a（增益/Gain）：控制图像的**对比度**，a大于1会扩大颜色差异，让亮处更亮，暗处更暗
* b（偏置/Bias）：控制图像的**亮度**，增加b会让整个图像的像素值整体提升

### 核心工具

在进行线性运算时，结果可能会超出uchar的范围

```c++
cv::saturte_cast<uchar>(value)
```

上述方法会自动进行边界检查，如果大于255，返回255，小于0，返回0，并且会将值强转为uchar

```c++
cv::Mat image = cv::imread("../static/test.png");
cv::Mat new_image = cv::Mat::zeros(image.size(), image.type());

for( int y = 0; y < image.rows; y++ ) {
    for( int x = 0; x < image.cols; x++ ) {
        for( int c = 0; c < image.channels(); c++ ) {
            // 获取原像素，计算线性变换，执行饱和转换
            new_image.at<cv::Vec3b>(y,x)[c] =
                cv::saturate_cast<uchar>( 3 * image.at<cv::Vec3b>(y,x)[c] + 10 );
        }
    }
}

cv::imshow("", new_image);
cv::waitKey();
```

**实际开发中推荐使用`convertTo`函数**

```c++
cv::Mat image = cv::imread("../static/test.png");
cv::Mat new_image = cv::Mat::zeros(image.size(), image.type());

image.convertTo(new_image, -1, 3, 15);

cv::imshow("", new_image);
cv::waitKey();
```

## 并行化

### 使用方法

通过使用`cv::parallel_for`，它是OpenCV提供的一个高层抽象API，屏蔽了底层的线程管理

### 两种实现方式

* **Lambda表达式**

  ```c++
  cv::parallel_for_(cv::Range(0, rows), [&](const cv::Range& range) {
      for (int r = range.start; r < range.end; r++) {
          // 对每一行进行处理的逻辑
          uchar* ptr = image.ptr<uchar>(r);
          for (int c = 0; c < cols; c++) {
              // 像素处理逻辑...
          }
      }
  });
  ```

* **继承`ParallelLoopBody`类**

  定义一个类继承，然后重载`oprator()`方法

### 并行化优势

* **分块策略**：会自动将图像切割成若干小块，每个核心负责处理其中一个小块，极大的提高了处理大图时吞吐
* **降低延迟**：大幅度降低处理的延迟
* **计算密集型任务**：多核加速的加入，能够让项目加入更急复杂的数学运算

### 并行化禁止操作

* **不能写入同一变量**：并行循环内部可以自由读取外部数据，但是绝不能同时向一个非线程安全的变量写入数据
* **不能过度并行**：如果任务非常简单，线程创建和调度的开销可能比计算本身更大
* **按行切割**：处理图像时，通常对hang进行Range切分，这样可以保持内存连续性，提高CPU缓存命中率
