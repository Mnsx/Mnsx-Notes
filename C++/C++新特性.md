# C++新特性

## 创建对象

C++11指定初始化值的方式包括

```c++
int x(0);
int y = 0;
int z{0};
int z = {0}; // 这种也是可以的
```

**不可复制的对象，可以采用大括号和小括号进行初始化，但是不能使用=**

综上所诉，大括号被称为统一初始化的原因在于，**大括号能够用于所有场合**

大括号初始化有一项新的特性，**他禁止内建类型之间进行隐式窄化类型转换**

```c++
double x, y;
int sum {x + y}; // 禁止
```

大括号初始化有一项特性是，对于C++解析语法免疫，C++规定**任何能够解析为声明的都要解析为声明**

```c++
Widget w1(); 
```

上述的初始化方法，会被编译器认定为声明一个函数，而非调用无参构造函数

由于函数声明不能使用大括号来指定形参列表，所以能够免疫上述问题

大括号初始化的缺陷在于，大括号初始化物、std::initializer_list以及析构函数重载决议之间存在问题，这几者之间相互作用的结果，可能与预期结果不同

如果在构造函数被调用时，只要形参中没有任何一个具备`std::initializer_list`类型，那么小括号和大括号的意义就没有区别，但是如果有，那么**大括号初始化语法的调用语句就会优先使用带有std::initializer_list类型形参的重载版本**，即使是移动或者复制都可能会被std::initializer_list类型挟持

编译器将大括号初始化物优先匹配带有std::initializer_list类型形参的构造函数，甚至会在带有std::initializer_list类型形参的构造函数无法被调用时

```c++
class A {
    
public:
	A(int i, bool b);
    A(std::initializer_list<bool> ilb);
};

A a(10, true);
```

上述代码会编译不通过，因为编译器会忽略第一个，选择第二个构造函数，而调用这个函数要求把两个参数转成bool类型，而将这两个类型都强制类型转换属于是窄化，是被大括号初始化语法禁止的，所以导致整段代码无法通过编译

只有在编译器无法将大括号初始化中的实参转换为std::initializer_list模板中的类型时，才会退而去检查普通的重载决议

```c++
class B {
    
public:
    B(int i, bool b);
    B(std::initializer_list<std::string> ils);
};

B a(10, true);
```

因为无法将int和bool类型隐式转换为string类型，所以编译器才会去查找普通的重载决议

而对于大括号中内容为空时，**语法规定，这种情况下应该执行默认构造**，而不是使用“空的std::initializer_list“

## 优先选用nullptr

正常使用0或者NULL的观点在指针类型和整型之间进行重载时可能会发生意外

```c++
void f(int);
void f(void *);

f(0);
f(NULL);
```

上述情况中，f(0)调用的时f(int)，而f(NULL)可能无法通过编译，但是一般会调用f(int)，绝对不会调用f(void *)

这样的原因在于0和NULL在C++中本质就是整型，而不是空指针，**而nullptr的优点在于，它不具备整型类型**，nullptr的实际类型是`std::nullptr_t`，并且类型std::nullptr_t可以隐式转换到所有的裸指针类型，这就是为什么nullptr可以扮演所有类型指针的原因

使用nullptr可以同时判断为0和为空两种类型，可以在使用auto声明不清楚返回值时，避免多义性的问题

## 优先别名声明

C++11提供别名声明

```c++
using UPtrMapSS = std::unique_ptr<std::unordered_map<std::string, std::string>>;
```

选择优先使用 别名声明而不是typedef的主要原因在于模板，**别名声明可以模板化**

```c++
// 使用别名声明
template <typename T>
using MyAllocList = std::list<T, MyAlloc<T>>;

MyAllocList<Widget> lw;

// 使用typedef
template <typename T>
struct MyAllocList {
    typedef std::list<T, MyAlloc<T>> type;
}

MyAllocList<Widget>::type lw;
```

并且如果使用typedef来创建一个容器，他的容纳对象类型由模板形参指定的话，需要在typedef前加上typename前缀

```c++
template <typename T>
class Widget {
private:
    typename MyAllocList<T>::type list;
}
```

这里的MyAllocList<T>::type代表一个依赖于模板类型形参的类型，所以它被成为带依赖类型，在C++中这种带依赖类型必须在前面加上typename

而是用别名声明就不需要

```c++
template <typename T>
using MyAllocList = std::list<T, Malloc<T>>;

template <typename T>
class Widget {
private:
    MyAllocList<T> list;
}
```

## 优先选用限定作用域的枚举类型

**如果在一堆大括号里声明一个名字，则该名字的可见性就被限定在括号括起来的作用域内**

而这种说法不适用于C++98风格的枚举类型中定义枚举量

```c++
enum Color {black, whilte, red};

auto white = false; // 报错
```

上述的代码就能够说明你，C++98中枚举量的名字泄露到了模具类所在的作用域，这就催生出了一个官方话术：**不限范围的枚举类型**，而在C++11中的对等物，限定作用域的枚举类型，就不会泄露

```c++
enum class Color {black, white, red};

auto white = false; // 不会报错

Color c = whilte; // 报错
Color c = Color::white; // 通过
```

由于限定作用域的枚举类型时通过`enum class`声明的，所以也被成为枚举类

优先选择使用枚举类的原因还有，**枚举类的枚举量时更强类型的**，而不限定范围的枚举类型中的枚举量可以隐式转换到整数类型

C++11中，不限范围的枚举类型和枚举类都可以进行前置声明，但是不限范围的枚举类型需要完成一些额外工作之后，这个工作就是由编译器确定选择一个整数类型作为枚举类型的底层类型

```c++
enum Status {good = 0, indeterminate = 0xFFFFFFFF};
```

上述枚举类型的取值范围从0到0XFFFFFFFF，编译器一般会选择比char更大尺寸的整数类型来表示，**为了节约使用内存，编译器通常会为枚举类型选用足够表示枚举量的最小底层类型**，而在某些情况下，编译器会用空间换时间，这样就可能不选择只具备最小克荣尺寸的类型，还需要具备优化空间的能力，为了实现这个可能，C++98就只提供了枚举类型的定义，而声明则是不允许的

C++11中枚举类型可以进行前置声明而C++98不可以的原因在于，**限定作用域的枚举类型的底层类型是已知的**

默认情况下，枚举类的底层类型是int，如果默认类型不符合开发要求，可以修改

```c++
enum class Status: std::uint32_t;
```

## 删除函数

在C++中编译器有时会自动声明函数，如果想要阻止调用者，在C++98中是通过将其声明为private，并且不去定义它们，而在C++11中，可以**使用delete，将复制构造函数和赋值运算符标识为删除函数**

删除函数无法通过任何方式使用，而private函数还是可以在类中或者友元函数中调用

习惯上，**删除函数应该被声明为public**，因为当函数被调用时，C++会先校验可访问性，然后再校验删除状态，这样，如果是private，用户只会知道函数被设置为私有，而不知道函数处于删除状态

删除函数的一个重要优点在于，任何函数就能成为删除删除函数，但只有成员函数能声明成private

删除函数还可以用来阻止不应该进行的模板具现

```c++
template <typename T>
void processPointer(T * ptr);
```

在指针世界中有两个异类，一个是void *指针，因为无法对其执行提领、自增、自减等操作，另一个是char *指针，因为基本上表示的是C风格的字符串，而不是指涉到单个字符的指针

所以上述函数应该禁止这两种类型的指针调用

```c++
template <>
void processPointer<void>(void *) = delete;

template <>
void processPointer<char>(char *) = delete;
```

## override声明

C++11在C++98的重写规则中又增加了一条，基类和派生类中的函数引用修饰词必须完全相同

> 成员函数引用修饰词是C++11中的语言特性，为了实现限制成员函数仅用与左值或右值，带有引用修饰词的成员函数，不必是虚函数

在重写父类虚函数时，可能会存在没有按照规范的点，但是有些问题编译器可能不会提示错误，C++11就针对这个问题提供了一种方法来显式表明派生类中的方法是为了改写积累版本，override声明

## 优先选用const_iterator

const_iterator是STL中相当于指涉到const的指针的等价物，他们指涉到不可被修改的值，**任何情况，只要需要一个迭代器，而其指涉的内容没有修改的必要，就应该使用const_iterator**

在C++11中，获取和使用const_iterator变得容易，容器的成员函数cbegin和cend都返回const_iterator类型，甚至对非const容器也是如此，并且STL成员函数若要取用只是位置的迭代器，也要求使用const_iterator

**但是在C++11中仅仅添加了非成员函数版本的begin和end，而没有添加cbegin、cend等**

在C++11中可以自己实现

```c++
template <typename C>
auto cbegin(const C & container) -> decltype(std::begin(container)) {
    
    return std::begin(container);
}
```

在通用代码中应该尽量使用非成员函数的begin、end等，而不是使用成员函数的实现，这是因为非成员函数版本能**兼容所有容器，STL容器、普通数组、自定义容器、任何标准兼容类型**

## noexcept声明

函数是否加上noexept声明，事关接口设计，调用者可以查询函数的noexcept状态，而查询结果会影响调用代码的异常安全性或运行效率，**当知道一个函数不会发射一场却未添加noexception声明的话，这就是接口规范缺陷**

在移动操作、swap操作时应该尽量加上noexcept声明，这会使代码运行更快

加上noexcept不会强制不抛异常，如果在加上noexcept声明的函数中抛出了异常，那么就会发出terminate信号

## constexpr

### constexpr对象

这些对象具备const属性，并且在编译阶段已知，在编译阶段已知的值拥有一些权限

比如，它们可能被防止在只读内存中，在编译阶段就已知的常量整型值可以用在C++要求整型常量表达式的语境中，这些语境包括数组的尺寸规范、整形模板实参、枚举量的值、对齐规格等

### constexpr函数

constexpr函数可以用在要求编译器常量的语境中，在这样的语句中，**若传给constexpr函数的实参值是在编译器已知的，那么结果也会在编译器间计算出来，如果任何一个实参值在编译期未知，则代码无法通过编译**

在调用constexpr函数时，**如果传入的值有一个或多个编译器未知，则它的运作方式将会和普通函数无异**，如果函数执行的是同样的操作，仅仅应用的语句是一个要求编译期常量，一个用于所有其他值的话，只需要一个constexpr修饰的函数即可

由于constexpr函数必须在传入编译器常量时能够返回编译器结果，他的实现就必须加以限制

* 不能访问运行时变量

* 不能做复杂操作

* 不能有循环、分支（早期 C++11）

* 不能调用非 constexpr 函数

* 不能有内存操作

在C++11中，constexpr函数不得包含多余一个可执行语句，即只能有一条return语句，而在C++14时放开了限制

constexpr函数仅限于传入和返回字面类型，意思就是这样的类型能够持有编译器可以决议的值，**在C++11中，所有的内建类型，除了void，都符合要求**

## 特种成员函数的生成机制

特种成员函数是指C++会自动生成的成员函数，C++98中有四种特种成员函数：默认构造函数、析构函数、复制构造函数以及复制赋值运算符重载，**这些函数仅在需要时才会生成**，即仅当代码使用时，而在类中并未显式声明的场合

**生成的特种成员函数都具有public访问层级且是inline的，而且它们都是非虚的**，除非是析构函数，且位于一个派生类中，基类是虚函数，这种情况下，编译器为派生类生成的析构函数也是虚函数

C++11中新增了**移动构造函数和移动赋值运算符**

```c++
public:
	Widget(Widget && rhs);
	Widget & operator=(Widget && rhs);
```

移动构造函数也是按需生成，**执行的也是作用非静态成员的按成员移动操作**，移动构造函数按照其形参的各个非静态成员对于本类的对应成员执行移动构造，而移动赋值运算符则依照其形参的各个非静态成员对于本类的成员执行移动赋值，**并且同时会移动基类部分**

按成员移动实际更多像是按成员的移动请求，**因为不可移动的类型将通过赋值操作实现移动**移动操作的核心在于把`std::move`应用于每一个移动源对象，其返回值被用于函数重载决议，是移动还是复制

两种复制操作是彼此独立的，声明了其中一个，并不会阻止编译器生成另一个，复制构造函数和复制赋值运算符，可以单独生成

**两种移动操作并不彼此独立**，声明其中一个，就会阻止编译器生成另一个，如果声明的移动构造函数与编译器生成的默认构造函数不同，那么按照默认移动赋值运算符就会出现问题

**甚至一旦显示声明了复制操作，这个类就不会生成移动操作**,声明复制操作的行为表明对象的常规复制途径对该类并不适用，因为默认的移动可能会转变成复制操作，为了避免这种问题，编译器会阻止自动生成移动

反之亦然，**一旦声明了移动操作，编译器就会废除复制操作**，因为如果成员的移动不是默认移动方式的话，复制也就没理由和默认相同

移动操作的生成条件仅当三者同时满足

* 该类未声明任何复制操作
* 该类未声明任何移动操作
* 该类未声明任何析构函数

如果说已经不满足编译器自动生成的条件了，但是编译器生成的这些函数有着正确的行为，那么可以通过`default`来显示标识

**更好的策略是，将这些函数自行声明，并用`defualt`定义**

**C++11中，支配特种成员函数的机制如下**

* **默认构造函数**：仅当类中不包含用户声明的构造函数时才生成
* **析构函数**：析构函数默认未noexcept，仅仅当基类的析构函数为虚时派生类的析构函数才是虚
* **复制构造函数**：运行期行为，按成员进行非静态数据成员的复制构造，仅当类中不包含用户声明的复制构造函数时才生成，**如果该类声明了移动操作，复制操作也会被删除，在已有复制赋值运算符或析构函数的条件下，仍然生成复制构造函数已经被废除**
* **复制赋值运算符**：运行期行为，按成员进行非静态成员的复制赋值，仅当类中不包含用户声明的复制赋值运算符时才生成，**如果该类声明了移动操作，复制操作也会被删除，在已有复制构造函数或析构函数的条件下，仍然生成复制赋值运算符已经被废弃**
* **移动构造函数和移动赋值运算符**：按成员进行非静态数据成员的移动操作，仅当类中不包含用户声明的复制操作、移动操作和析构函数时才生成
