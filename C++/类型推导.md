# 类型推导

## 模板类型推导

在模板函数中，编译器在编译期会根据调用函数，expr来判断两个类型，一个是T也就是模板参数的类型，还有一个就是ParamType的类型，ParamType的类型可能与T不同，因为ParamType经常会包含一些修饰如const

```c++
template <typename T>
void f(ParamType param);

f(expr);
```

在正常情况下，通常会认为，T的类型与函数调用expr的类型相同，但是并非如此，推断T的类型还需要使用ParamType，具体可以分为三种情况

### ParamType为指针或引用

如果ParamType是指针或者引用，但不是万能引用时

1. 若expr具有引用类型，先将引用部分忽略
2. 然后，对expr的类型和ParamType的类型执行模式匹配，来决定T的类型

### ParamType为万能引用

万能引用的声明方式类似右值引用（即在函数模板中持有模板参数类型T时，万能引用的声明类型写作T&&），**但是传入的实参时左值时，表现会有所不同**

* 如果expr是个左值，T和ParamType都会被推倒为左值引用

  **这是在模板类型推导中，T被推导为引用的唯一情形**

  并且，尽管声明是使用的右值引用，但是推导类型结果还是左值引用

* 如果expr是个右值，则应用第一种情况

### ParamType非指针非引用

如果并非指针和引用，那么久是值传递了

如果expr具有引用类型，则忽略其引用类型，如果expr是个const对象，则忽略其const修饰符，如果是volatile对象，同样忽略其volatile修饰符

> 考虑传递`const char  * const ptr`时的情况
>
> 首先，位于星号右侧的const表示ptr不可以指向其他内存位置，也不可以被置为nullptr，位于型号左侧的const表示字符串不能修改
>
> 可在ptr传递给函数时，这个指针本身会按bite复制给param，所以说ptr是**按值传递**，根据按值传递的推导规则，**ptr的常量性会被忽略**，类型将会被推导为`const char *`
>
> 但是在复制创建新指针param时，**ptr指向对象的常量行也会被忽略**

### 数组实参

数组类型有别于指针类型，在很多语境下，数组会退化成指向首元素的指针

由于这个原因，按值传递给函数模板的数组类型将被推导成指针类型

函数可以将形参声明成数组的引用，这样按引用传递参数，**T的类型会被推导成史记的数组类型**，这个类型中会包含数组的长度

```c++
template <typename T, std::size_t N>
constexpr std::size_t arraySize(T (&)[N]) noexcept {
    
    return N;
}
```

### 函数实参

函数类型也会退化成函数指针，数组指针的情况也同样适用于函数指针

## auto类型推导

auto类型推导机制几乎和模板类推导机制相同，只有一种情况不同

C++98提供两种赋初始值的方法，C++11为了支持统一初始化，增加了两种方法，共计四种语法，如果使用auto声明，则代码如下

```c++
auto x1 = 7;
auto x2 = x2(7);
auto x3 = {7};
auto x3{7};
```

但是如果使用auto进行声明，会导致前两种声明了int变量，但是后两种声明的是类型为`std::initializer_list<int>`类型的变量

这是关于auto的特殊类型推导机制导致，当auto声明变量的初始化表达式是使用大括号时，**推导所得的类型就属于`std::initializer_list`**，这样设计的原因在于，如果类型推导失败（如大括号值类型不同），则代码就无法通过编译

这种使用大括号进行初始化的方式对于auto而言，会将其推导成`std::initializer_list`而**模板类则无法进行类型推导**

在C++14中，允许使用auto来声明函数返回值类型，而且Lambda表达式中，也会在形参声明中使用auto，然而，**这些auto的用法使用模板类型推导**，无法编译大括号的初始化表达式

## decltype

decltype通常情况返回给定的名字或表达式的确切类型，在C++11中，decltype的主要用途就在于声明那些返回值类型依赖于形参类型的函数模板

```c++
template <typename Container, typename Index>
auto authAndAccess(Container & c, Index i) -> decltype(c[i]) {
    
    authenticateUser();
    return c[i];
}
```

上述代码函数名字之前使用的那个auto和类型推导没有任何关系，它只是说明这里使用了**C++11中的返回值类型尾序语法**，这种写法的好处在于**可以在指定返回值时使用函数的形参**

C++11中允许对Lambda表达式的返回值进行类型推导，而C++14中则允许一切函数进行返回值类型推导，这表明不需要使用上述的尾序语法

```c++
template <typename COntainer, typename Index>
auto authAndAccess(Container & c, Index i) {
    
    authenticateUser();
    return c[i];
}
```

如auto类型推导中所说，这样使用auto推导类型，会按照模板类型推导机制进行，而大多数含有类型T的对象的容器，调用`operator[]`会返回T&，这样导致下述的问题

```c++
std::deque<int> d;
...
authAndAccess(d, 5) = 10;
```

d[5]的返回值应该是int&，而根据auto类型推导机制，对返回值推导，返回的类型应该是int类型，**作为函数的返回值，这个int类型属于是右值**，而上述代码中试图将右值赋值给右值，这是禁止的

想要上述功能能够成功实现，就需要对返回值进行decltype类型推导

```c++
template <typename Container, typename Index>
decltype(auto) authAndAccess(Contianer & c, Index i) {
	authenticateUser();
    return c[i];
}
```

这种使用decltype类型推导机制的方法，也可以使用在其他位置

容器的传递方式是对非常量的左值引用，因为返回该容器的元素的引用，就意味着允许用户修改这个容器，这也以为着无法向该函数传递右值容器，**右值不能绑定到左值引用中，除非是对常量的左值应用**，所以这个时候就需要使用万能引用，并且使用万能应用时需要使用`std::forward`

```c++
template <typename Container, typename Index>
decltype(auto) authAndAccess(Conntainer && c, Index i) {
    
    authenticateUser();
    return std::forward<Container>(c)[i];
}
```
