# 模板与泛型

## 隐式接口和编译器多态

使用模板，使得这一组表达式便是T必须支持的一组隐式接口

凡涉及函数调用，这样的具体实现行为发生在编译器会导致调用不同的函数，这便是所谓的编译器多态

## typename双重意义

template内出现的名称如果相依于某个template参数，称之为**从属名称**，如果从属名称在class内呈嵌套状，我们称之为**嵌套从属名称**

如果解析器在template中遭遇一个嵌套从属名称，**它便会假设这个名称不是个类型**

```c++
template <typename C>
C::const_iterator iter;
```

上述的`C::const_interator`在解释器中便不是一个类型，如果要告诉解释它他是一种类型，就需要使用关键字`typename`

```c++
template <typename C>
typename C::const_iterator iter;
```

任何时候需要在`template`中指涉一个**嵌套从属类型名称**，就必须在紧邻它的前一个位置放上关键字`typename`

**但是**，typename不可以出现在**基类声明列表内的嵌套从属类型名称之前**，也不可以出现在**成员初值列表中**

```c++
template <typename T>
class D : public B<T> { // 不允许出现typename
public:
    explicit D(int x) : Base<T>(x) {} // 不允许出现typename
};
```

## 隐式实例化、显式实例化、显示具体化

### 隐式实例化

当在代码中使用一个模板类的具体类型时，编译器会自动生成该类型的模板类代码

```c++
template <typename T>
class MyTemplate {
public:
    T value;
    ...
};

MyTemplate<int> obj;
```

* **自动完成**
* **按需生成**
* **最常用**

### 显式实例化

通过特定的语法，明确告诉编译器生成这个类型的模板类代码，无论当前代码是否立即使用它，`template class 模板类名<具体类型>;`

```c++
template <typename T>
class MyTemplate {
public:
    T value;
    ...
};
template class MyTemplate<int>; //

MyTemplate<int> obj;
```

* **控制编译时机**，加快编译速度减少代码冗余
* **提前发现错误**，显示实例化会强制编译器检查模板代码是否出现语法错误

### 显式具体化

当模板的通用实现对某种特定类型不适用或效率低下时，可以单独为这个类型编写一份完全不同的类定义，`template <> class 模板类名<具体类型>`

```c++
template <typename T>
class MyTemplate {
public:
    T value;
};
template <> class MyTemplate<string> {
public:
    string value;
};
```

* **优化特定类型**
* **处理特殊逻辑**

## 模板类中基类名称

因为编译器知道基类模板有可能被显式具体化，而新的具体化版本可能不提供和一般性template相同的接口，所以**它往往拒绝在模板化基类中寻找继承而来的名称**

避免这个问题有三个办法：

* **在基类函数调用动作之前加上`this->`***

  ```c++
  template <typename T>
  class A : public B<T> {
  public:
      ...
      void a(const C & c) {
          this->b(c);
      }
  }
  ```

* **使用`using`表达式**

  ```c++
  template <typename T>
  class A : public B<T> {
  public:
      using B<T>::b;
      void a(const C & c) {
          b(c);
      }
  }
  ```

* **明确指出被调用的函数位于基类中**

  ```c++
  template <typename T>
  class A : public B<T> {
  public:
      void a(const C & c) {
          B<T>::b(c);
      }
  }
  ```

  这种解法存在问题，**如果被调用的是`virtual`函数，那么上述的明确修饰会关闭`virtual`的绑定行为**

## 成员函数模板

需求中可能需要两个不同类型的模板类之间可以进行交互或者转化，比如智能指针需要实现原生指针中的相互转化效果

可以通过模板成员函数实现

```c++
template <typename T>
class A {
public:
    template <typename U>
    A(const A<U> & other);
}
```

上述代码的含义是，对任何类型T和任何类型U，可以根据`A<T>`生成一个`A<U>`，这种实现成为**泛型复制构造函数**

**在类中声明泛型复制构造函数并不会组织编译器生成默认的复制构造函数**，如果想要去除默认的复制构造，就必须同时**声明泛型复制构造函数和正常的复制构造函数**，相同的规则同样适用于**赋值操作**

## 使用非成员函数操作类型转换

**模板参数推导不考虑隐式类型转换**，将非成员函数定义为模板类的友元函数（并在类中实现）

当模板类被实例化时，友元函数也会被自动实例化，这是参数类型明确的指向`const A<int> &`

当调用需要进行类型转化的函数时，编译器看到的是一个参数为`const A<int> &`的函数，他就会尝试将第二个实参隐式转化为`A<int>`类型

使用友元函数**绕过了模板参数推导**，因为友元函数是**在模板类实例化时才确定其具体类型**

## TraitsClasses

`Traits Classes`（特行类）是一种模板类，它的主要作用是**封装类型的属性信息**

* **类型信息的查询**
* **基于类型属性的行为定制**
* **增强代码的通用型和灵活性**

### 工作原理

`Traits Classes`的实现总是依赖于**C++的模板特化**机制

1. **定义通用模板**：首先定义一个通用的`traits`模板类，它包含一些默认的类型定义、常量和函数，**这个通用版本通常处理的是默认情况或未知情况**
2. **提供特化版本**：然后，为需要的特定类型或类型类别提供该`traits`类的特化版本，在这些特化版本中**可以为类型定制其特有的属性信息**

### 简易实现

```c++
// 通用模板：默认情况下，类型不是整数类型
template <typename T>
struct is_intergral {
    static const bool value = false;
}
// 为int类型提供特化版本
template <typename T>
struct is_intergral<int> {
    static const bool value = true;
}
template <typename T>
struct is_intergral<long> {
    static const bool value = true;
}
template <typename T>
void printTypeCategory(const T & value) {
    if (is_integral<T>::value) {
        // 复合条件的执行
    } else {
        // 不复合条件的执行
    }
}
```
