# 继承

## 公有继承

公有继承意味着`is-a`，适用于基类的每一件事情都应该适用于派生类中

## 作用域问题

**内层作用域的名称会掩盖外围作用域的名称**

同样继承关系中，子类的函数也会掩盖父类的同名函数

如果正在使用公有继承但是不继承重载函数，就是违反了基类和派生类之间的`is-a`关系

**可以使用`using`声明式来推翻C++这种缺省遮掩行为**

```c++
class Base {
public:
    void f3();
    void f3(int);
};
class Derived : public Base {
public:
    using Base::f3;
    void f3();
};
// 这样通过子类调用父类的f3(int)就不会报错了
Derved d;
d.f3(10);
```

如果是私有继承，就没法使用`using`的方法，应为继承后的父类函数，在子类中是私有的，**而`using`声明式会令继承而来的同名函数在子类中可见，这违反了私有继承，**这种情况下就应该使用转交函数

```c++
class Base {
public:
    void f3();
};
class Derived : private Base {
public:
    void f3() {
        Base::f3();
    }
};
```

## 接口继承和实现继承

声明一个纯虚函数的目的是**为了让派生类只继承函数接口**

声明非纯虚函数的目的是**让派生类继承该函数的接口和缺省实现**

可以利用纯虚函数必须在派生类中重新声明但是可以拥有自己的实现这一点，解决接口和默认实现应该分开的问题

声明非虚函数的目的是**为了令派生类继承函数的接口及一份强制性实现**

## 虚函数意外的做法

### 通过非虚函数实现模板方法模式

这个设计就是**令客户通过公有非虚成员函数间接调用私有虚函数**，称为NVI手法

这意味外覆器（wrapper）确保得以在一个虚函数被调用之前设定好适当场景，并在调用结束之后清理场景

```c++
class A {
private:
    virtual void a() {
        ... // 默认实现
    }
public:
    void doA() {
        a(); // 通过非虚函数调用虚函数
    }
}
```

### 基于函数指针实现策略模式

要求每个对象的构造函数接受一个指针，指向一个算法函数，而实际上就是调用该函数进行实际计算

这样的实现允许同一个类型的不同对象，可以有不同的处理算法函数，并且已知的对象的算法函数可以在运行期间变更，可以提供一个set函数，用来替换当前的算法函数指针

```c++
class A;
int defaultA(const A & a);
typedef int (*AFunc)(const A &);
class A {
private:
    AFunc afunc;
public:
    explicit A(AFunc afunc = defaultA) : AFunc(afunc) {}
};
```

### 基于std::function完成策略模式

传统函数指针的缺点在于

* 必须是**全局函数**
* 参数、返回值**必须完全匹配**
* 不能用**成员函数**
* 不能用**函数对象**
* 不能用Lambda函数

`std::function`是一个**万能可调用对象包装器**，可以包装

* 普通函数
* 函数对象
* Lambda表达式
* 甚至bind绑定后的函数

```c++
class A;
int defaultA(const A & a);
using AFunc = std::function<int(const A &)>; // 只兼容int fun(const A & a)
class A {
private:
    AFunc aFunc;
public:
    explicit A(AFunc aFunc = defaultA) : aFunc(aFunc) {}
}
```

### 古典策略模式实现

```c++
class A;
class AFunc {
    virtual int doFun(const A & a) const {
        ...
    }
};
AFunc defaultA;
class A {
private:
    AFunc * aFunc;
public:
    explicit A(AFunc * aFunc = &aFunc) : aFunc(aFunc) {}
};
```

## 不应该重新定义继承

* **非虚函数**

  因为`virtual`函数是**动态绑定**，所以他不会受到名称掩盖的问题

  **任何情况下都不该重新定义一个继承而来的非虚函数**

* **缺省参数值**

  虚函数是动态绑定的，而**缺省参数是静态绑定**

## is-a和is-implemented-in-terms-of

`is-implemented-in-terms-of`是根据某物实现出来的对象关系

> set的实现往往招致**每个元素消耗三个指针**的额外开销，因为set通常以平衡查找树实现而成

简单的理解，set这个容器是基于list这个容器实现的，但是set不应该直接继承list，因为set是唯一的，而list中是重复的，这违反了`is-a`这个原则

```c++
template <typename T>
class Set {
private:
    list<T> setList;
public:
    ...
};
```

上述实现就是通过`is-implemented-in-terms-of`实现的复合关系

## 慎用私有继承

如果是私有继承，**编译器不会自动将一个派生类对象转换为一个基类对象**

**私有继承意味着`implemented-ini-terms-of`**

尽可能通过复合实现`implemented-in-terms-of`而不是使用私有继承

* 私有继承的方式，**那么该类的派生类将无法访问私有继承得到的东西**，而复合可以
* 使用私有继承，那么对象被编译时他的父类也必须可见，所以可能需要通过`#include`添加父类声明，而使用复合，因为对象中已经带有所需对象的实现，所以不需要在添加引用了

## 慎用多重继承

多重继承的主要问题在于**菱形继承**

通过虚继承机制可以解决，在继承链中，当一个类被多个后续类继承时，在继承它的时候应该加上`virtual`关键字，这会告诉编译器，**无论该类在继承链中出现多少次，只保留一份实例**

**虚继承会带来一定的性能开销（额外的指针和间接访问导致）**
