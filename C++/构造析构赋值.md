# 构造/析构/赋值

## 默认生成

C++默认为类生成**复制构造函数**，**赋值运算符重写**和**析构函数**

这个默认的析构函数不是`virtual`声明的

对于含有不能进行赋值操作变量（内含references成员、内含const成员）的类进行赋值操作时，C++的响应是**拒绝编译那一行赋值动作**

## 拒绝默认生成

如果不需要编译器提供的默认函数，应该将其声明为私有

```c++
class A {
private:
    A(const A &);
    A & operator=(const A &);
};
```

A类可以作为接口类，**后续类可以通过继承A**，限制禁止默认复制和赋值的使用

```c++
class B : private A {
    ...
}
```

虽然编译器会自动给B生成默认函数，但是B调用时会因为无法调用父类的函数，导致调用失败

## 多态析构声明

在多态中，应该使用`virtual`修饰析构函数

实现`vitual`函数，对象必须携带信息，信息通常由一个vptr（virtual table pointer）指针指出，vptr指向一个由函数指针构成的数组，成为vtbl（virtual table），**实际调用函数取决于该对象的vptr所指出的vtbl**

也就是说，如果类中含有`virtual`函数，**其对象的体积会增加**，所以说在没有多态需求的类中，实现虚析构函数也是错误的

**不应该继承没有提供虚析构函数的类**

## 避免析构抛出异常

如果选择在析构函数中抛出错误，如果两个析构函数同时抛出错误，在程序不停止运行的情况下，可能会意想不到的结果，所以在开发过程中应该**避免在析构函数中抛出异常**

* **如果析构函数抛出异常就结束程序**，通常通过`abort`函数完成

* **捕获因调用`close`而发生的异常**

  ```c++
  A:~A() {
      try {
          ... // 异常
      } catch (...) {
          ... // 记录日志
      }
  }
  ```

  因为直接捕获异常，**可能会导致后续出现更严重异常**

* **提供普通函数执行析构操作**，如果用户需要对某个操作函数运行期间抛出的异常进行反应，那么类应该提供一个普通函数执行该操作

## 构造/析构中禁止调用虚函数

构造或析构都会优先调用基类的相应函数，如果在构造或析构中声明了虚函数，**在基类构造或析构过程中，虚函数不是虚函数，不会根据对象的类型调用**，而是直接调用基类的方法，可能会导致程序出现问题

## 在赋值运算符重载中处理“自我赋值”

```c++
A & A::operator=(const A & a) {
    delete pa;
    pa = new A(a.pa);
    return *this;
}
```

如果是上述情况，如果是自己调用自己的赋值运算符，那么在执行`delete pa`时，**也就已经将a中的数据清除**

```c++
A & A::operator=(const A & a) {
    if (this == &a) {
        return *this;
    }
    delete pa;
    pa = new A(a.pa);
    return *this;
}
```

可以像上述代码一样进行一个证同测试，或者可以像下述代码一样，在编写代码时，让`operator=`具备**异常安全性**

```c++
A & A::operator=(const A & a) {
    int * temp = pa;
   	pa = new int(a.pa);
    delete temp;
    return *this;
}
```

还可以使用**copy and swap**，类似于将引用传递修改为值传递

```c++
class A {
    void swap(A & a);
    A & A::operator=(const A & a) {
        A temp(a);
        swap(temp);
        return *this;
    }
}
```

## 复制时考虑所有成员

* **复制所有本地的成员变量**
* **调用所有基类内适当的复制函数**
