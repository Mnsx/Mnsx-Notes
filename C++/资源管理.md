# 资源管理

## 使用对象管理资源

应该将资源放进对象内，通过C++提供的析构函数自动调用机制确保资源被释放

类指针对象**auto_ptr**就是针对资源管理而创建的类，其析构函数自动对其所指对象调用delete

**获取资源后立即放进管理对象内**，资源取得时便是初始化时机（RAII）

**管理对象运用析构函数确保资源被释放**

**一定不能让多个智能指针指向同一对象**，这样对象可能会被删除一次以上

为了预防这个问题，`auto_ptrs`若通过复制构造函数或赋值运算符赋值进行复制操作，**会使得原本的智能指针变成`nullptr`**，而复制所得的指针将获得资源的唯一拥有权

因为这一特性，替代方案就是**引用计数形智能指针（RCSP）**，持续追踪共有多少对象指向资源，并在无人指向时自动删除该资源，但是**无法解决环状引用的问题**

**两款智能指针都是进行的delete操作，而不是[]**

## 资源管理类中谨慎使用复制行为

* **禁止复制**，许多时候允许RAII对象被赋值并不合理，所以直接可以禁止赋值行为

* **对底层资源使用引用计数法**，可以保有资源直到它的最后一个使用者被销毁，这种情况下，复制RAII对象时，**应该将资源的被引用数递增**

  > 当存在需要处理mutex时，可以选择使用**`trl::shared_ptr`**，它允许指定所谓的删除器，那是一个函数或函数对象，**当引用次数为0时便被调用**

* **复制底层资源**，某些情况下可以针对一份资源拥有任意数量复件，**这种情况下赋值资源管理对象，应该同时也复制其包含的资源，进行深度拷贝**
* **转移底部资源的拥有权**，某些情况需要保证只有一个RAII对象指向未加工资源，即使RAII对象被复制依旧如此，此时**应该将资源的拥有权移动到目标物中**，`auto_ptr`就是这个策略

**最常用的赋值策略是：禁止复制和引用计数法**

## 在资源管理类中提供对原始资源的访问

需要提供将RAII类对象转换成其所内含的原始资源的函数，有两种方法可以实现：显式转换和隐式转换

`trl::shared_ptr`和`auto_ptr`都提供一个`get`成员函数，用来执行显示转换，也就是返回**智能指针内部的原始指针（复件）**

并且所有智能指针一样，也都**重载了指针取值操作符（operator->和operator*）**，它们允许隐式转换至原始指针

```c++
class A {
public:
    operator B() const {
        return bObj;
    }
};
```

上述函数也属于隐式转换函数，允许将A转换为B

**一般而言显示转换更加安全，隐式转换对客户比较方便**

## 成对new和delete采取相同形式

如果`new`表达式中使用`[]`，那么必须在相应的`delete`表达式中也使用`[]`，如果在`new`表达式中没有使用`[]`，那么在相应的`delete`表达式中也不能使用`[]`

## 独立将对象置入智能指针

```c++
func(trl::shared_ptr<A>(new A), getA());
```

上述函数需要执行的内容包括：

1. 调用`getA()`函数
2. 执行`new A`表达式
3. 调用`trl::shared_ptr`构造函数

但是**C++编译器不一定按照所需的次序完成**，只能确认`new A`会在`trl::shared_ptr`之前执行，因为这个表达式的结果会作为`trl::shared_ptr`构造函数的实参，可能就会造成问题

如果`getA()`在第二号位执行，在调用过程中报错，那么就会导致`new A`返回的指针丢失，出现内存泄露

**避免这种方式，应该选择以独立语句将newed对象存储到智能指针中**
