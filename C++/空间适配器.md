# 空间适配器

## 空间配置器的标准接口

根据STL规范以下是`allocator`的必要接口

* **成员变量**

  ```C++
  allocator::value_type;
  allocator::pointer;
  allocator::const_pointer;
  allocator::reference;
  allocator::const_reference;
  allocator::size_type;
  allocator::defference_type;
  allocator::rebind; // 一个嵌套的模板类 rebind<U>
  ```

* **构造/析构函数**

  ```C++
  allocator::allocator(); // 默认构造函数
  allocator::allocator(const allocator &); // 复制构造函数
  template <class U>
  allocator::allocator(const allocator<U> &); // 泛式复制构造函数allocator::~allocator(); // 默认析构函数
  ```

* **成员函数**

  ```c++
  pointer allocator::address(reference x) const;
  
  const_pointer allocator::address(const_reference x) const; 
  ```

  上述两个函数用来返回某个对象或者某个const对象的地址

  ```C++
  pointer allocator::allocate(size_type n, const void * = 0);
  ```

  用来配置空间，足以存储n个T对象，第二参数是提示，实际上用它来增进区域性，或者完全可以忽视

  ```C++
  void allocator::deallocate(pointer p, size_type n);
  ```

  用来归还先前配置的空间

  ```c++
  size_type allocator::max_size() const;
  ```

  用来返回可成功配置的最大量

  ```C++
  void allocator::construct(pointer p, const T  x);
  ```

  用于在指定指针位置配置容纳T对象的空间

  ```C++
  void allocator::destroy(pointer p);
  ```

  用于释放p指针位置对应的空间，等同于`p->~T()`

## 设计简单空间配置器

> **PJ STL和RW STL区别**
>
> * PJ STL是给Windows VC++用的
>
> * RW STL是早期C++标准库
>
> * SGI STL是给Linux/GCC用的

```C++
/** 
 * @file Allocator.h
 * @author Mnsx_x <xx1527030652@gmail.com>
 * @date 3/23/26
 * @description 
 */
#ifndef TINYSTL_ALLOCATOR_H
#define TINYSTL_ALLOCATOR_H
#include <climits>
#include <cstddef>
#include <cstdlib>
#include <iostream>
#include <new>

namespace tinySTL {

    template <typename T>
    inline T * _allocate(std::ptrdiff_t size, T *) {

        std::set_new_handler(nullptr);
        T * temp = (T *) (::operator new((size_t) (size * sizeof(T))));
        if (temp == 0) {

            std::cerr << "out of memory" << std::endl;
            exit(EXIT_FAILURE);
        }
        return temp;
    }

    template <typename T>
    inline void _deallocate(T * buffer) {

        ::operator delete(buffer);
    }

    template <typename T1, typename T2>
    inline void _construct(T1 * p, const T2 & value) {

        new (p) T1(value);
    }

    template <typename T>
    inline void _destroy(T * ptr) {

        ptr->~T();
    }

    template <typename T>
    class Allocator {
    public:
        using value_type = T;
        using pointer = T *;
        using const_pointer = const T *;
        using reference = T &;
        using const_reference = const T &;
        using size_type = std::size_t;
        using difference_type = std::ptrdiff_t;

        template <typename U>
        struct rebind {

            using other = Allocator<U>;
        };

        pointer allocate(std::size_t n, const void * hint = nullptr) {

            return _allocate<T>(static_cast<difference_type>(n), static_cast<pointer>(nullptr));
        }

        void deallocate(pointer p, std::size_t n) {

            _deallocate(p);
        }

        pointer address(reference x) const {

            return static_cast<pointer>(&x);
        }

        const_pointer const_address(const_reference x) const {

            return static_cast<const_pointer>(&x);
        }

        size_type max_size() const {

            return static_cast<size_type>(UINT_MAX / sizeof(T));
        }
    };
}

#endif //TINYSTL_ALLOCATOR_H
```

上述的`Allocator`的简单实现，只能有限度搭配`PJ STL`和`RW STL`

* `PJ STL`未完全遵循STL规格，其所供应的许多容器都需要一个非标准的空间配置器接口`allocator::_Charalloc()`
* `RW STL`在续对容器上运用了**缓冲区**，情况复杂很多

## SGI空间配置器

SGI的空间配置器名称为`alloc`，而且不接受任何参数

`SGI STL`的每一个容易都指定其默认的空间适配器为`alloc`

```c++
template <class T, class Alloc = alloc>
class vector { ... }
```

### SGI标准的空间配置器

SGI也定义一个符合部分标准，名为`allocator`的配置器，但是因为**效率不假，只是对C++的`::operator new`和`::operator delete`做了包装**，所以不建议使用

### SGI特殊的空间配置器

C++中`new`运算符内含两阶段操作：（1）调用`::operator new`（2）调用构造函数

`delete`运算符内含两阶段操作：（1）调用析构函数（2）调用`::operator delete`释放内存

在`SGI STL`中，将两个阶段分别放在头文件中

```C++
#include <stl_alloc.h>
#include <stl_construct.h>
```

### 构造和析构

```C++
template <class T>
inline void destroy(T * pointer) {
    pointer->~T();
}
```

这是第一版本的`destroy()`，接受一个指针

```C++
template <class ForwardIterator>
inline void destroy(ForwardIterator first, ForwardIterator last) {
    __destroy(first, last, value_type(first));
}
```

这是第二版本的`destroy()`，接受两个迭代器，**此函数设法找出元素的数据类别，进而利用`__type_traits<>`求取最适当的措施**

```C++
template <class ForwardIterator, class T>
inline void __destroy(ForwardIterator first, ForwardIterator last, T *) {
    typedef typename __type_traits<T>::has_trivial_destructor trivial_destructor;
__destroy_aux(first, last, trivial_destructor());
}
```

这个函数用于判断元素的数值类别是否有`trivial destructor`

`__type_traits<T>`是STL的萃取器，用来提取T类型的特性

`has_trivial_destructor`用于判断是否有无用/平凡/空的析构函数，返回值为`true_type`析构函数为空的不用调用，`false_type`析构函数有用，必须调用

```C++
template <class ForwardIterator>
inline void __destroy_aux(ForwardIterator first, ForwardIterator last, __false_type) {
    for ( ; first < last; ++first) {
        destroy(&*first);
    }
}

template <class ForwardIterator>
inline void __destroy_aux(ForwardIterator, ForwardIterator, __true_type);
```

SGI中还提供了`char *`和`wchar_t *`的特化版本

```C++
inline void destroy(char *, char *) {}
inline void destroy(wchar_t *, wchar_t *) {}
```

### 空间的配置和释放

在SGI的实现中，针对空间配置和释放，考虑到了下面几点

* 向system heap要求空间
* 考虑多线程状态
* 考虑内存不足时的应变措施
* 考虑过多小型区块可能总成内存碎片的问题

**SGI中选择使用`malloc()`和`free()`完成内存的配置和释放**

考虑到**内存碎片问题**，SGI设计**双层级配置器**，第一级配置器直接使用`malloc()`和`free()`，第二级则根据情况采用不同的策略：**当配置区块超过128bytes时，调用第一级配置器，当配置区块小于128bytes时，为了降低额外负担，采用复杂的`memory pool`整理方式**，可以通过`__USE_MALLOC`是否被定义来选择，只开放一级还是同时开放二级

```c++
# ifdef __USE_MALLOC
...
typedef __malloc_alloc_template<0> malloc_alloc;
typedef malloc_alloc alloc; // 一级
# else
...
typedef __default_alloc_template<_NODE_ALLOCATOR_THREADS, 0> alloc; // 二级
# endif
```

但是无论`alloc`被定义为第一级或第二级配置器，SGI包装一个接口，使配置器的接口能够符合STL规格

```C++
template <class T, class Alloc>
class simple_alloc {
public:
    static T * allocate(size_t n) {
        return 0 == n ? 0 : (T *) Alloc::allocate(n * sizeof(T));
    }
    static T * allocate(void) {
        return (T *) Alloc::allocate(sizeof(T));
    }
    static void deallocate(T * p, size_t n) {
        if (0 != n) {
            Alloc::deallocate(p, n * sizeof(T));
        }
    }
    static void deallocate(T * p) {
        Alloc::deallocate(p, sizeof(T));
    }
}
```

### 第一级配置器

`malloc-based allocator`通常比`default alloc`速度慢，一般而言是`thread-safe`，并且对于空间利用比较搞笑

```c++
template <int inst> // alloc没有模板参数，所以inst完全没有被使用
class __malloc_alloc_template {
private:
    // 以下都是函数指针，用来处理内存不足的情况
    static void * oom_malloc(size_t);
    static void * oom_realloc(void *, size_t);
    static void (* __malloc_malloc_oom_handler) ();
public:
    static void * allocate(size_t n) {
        // 第一层配置器直接使用malloc()
        void * result = malloc(n);
        // 无法满足需求时，改用oom_malloc()
        if (0 == result)
            result = oom_malloc(n);
        return result;
    }
    static void deallocate(void * p, size_t /* n */) {
        // 第一层配置器直接使用free()
        free(p); 
    }
    static void * reallocate(void * p, size_t /* old_sz */, size_t new_sz) {
        // 第一级配置器直接使用realloc()
        void * result = realloc(p, new_sz);
        if (0 == result)
            result == oom_realloc(p, new_sz);
        return result;
    }
    
    // 通过这个函数可以指定自定义的OOM handler
    static void (* set_malloc_handler(void (* f)())) {
        void (* old)() = __malloc_alloc_oom_handler;
        __malloc_alloc_oom_handler = f;
        return (old);
    }
};  
    
// malloc_alloc oom handling，初始值为0,等待客户端设置
template <int inst>
void (* __malloc_alloc_template<inst>::__malloc_alloc_oom_handler)() = 0;

template <int inst>
void * __malloc_alloc_template<inst>::oom_malloc(size_t n) {
    void (* my_malloc_handler) ();
    void * result;
    // 不断尝试释放配置
    for (;;) {
        my_malloc_handler= __malloc_alloc_oom_handler;
        if (0 == my_malloc_handler) {
           	__THROW_BAD_ALLOC;
        }
        // 再次调用，试图释放内存
        (* my_malloc_handler)();
        // 再次尝试配置内存
       	result = malloc(n);
        if (result) {
            return (result);
        }
    }
}

template <int inst>
void * __malloc_alloc_template<inst>::oom_realloc(void * p, size_t n) {
    void (* my_malloc_handler)();
    void * result;
    // 同样的处理方式
    for (;;) {
        my_malloc_handler= __malloc_alloc_oom_handler;
        if (0 == my_malloc_handler) {
           	__THROW_BAD_ALLOC;
        }
        (*my_malloc_handler)();
        result = realloc(p, n);
        if (result) {
            return (result);
        }
    }
}

typedef __malloc_alloc_template<0> malloc_alloc;
```

### 第二级配置器

当区块小于128bytes时，痛殴各国内存池管理：**每次配置一大块内存，并维护对应的空闲链表，如果再有相同大小的内存需求，则直接从空闲链表中拨出**

SGI第二级配置器**会主动将任何小额内存需求量上调至8的倍数**，并维护16个空闲链表，对应大小分别为8、16、24、32、40、48、56、64、72、80、88、96、104、112、120、128

```c++
union obj {
    union obj * free_list_link;
    char client_data[i];
}
```

上述就是空闲链表的实现

```c++
enum {__ALIGN = 8}; // 小型区块的上调边界
enum {__MAX_BYTES = 128}; // 小型区块的上限
enum {__NFREELISTS = __MAX_YTES/__ALIGN}; // 空闲链表个数

template <bool threads, int inst>
class __default_alloc_template {
private:
    // 将bytes上调至8的倍数
    static size_t ROUND_UP(size_t bytes) {
        return (((bytes) + __ALIGN - 1) & ~(__ALIGN - 1));
    }
private:
	union ojb {
        union obj * free_list_link;
        char client_data[i];
    };
private:
    // 16个空闲链表
    static obj * volatile free_list[__NFREELISTS];
    // 根据区块大小决定使用第n号空闲链表，从1开始算
    static size_t FREELIST_INDEX(size_T bytes) {
        return (((bytes) + __ALIGN - 1) / __ALIGN - 1);
    }
    // 返回一个大小为n的对象，并可能加入大小为n的其他区块到空闲链表
    static void * refiil(size_t n);
    // 配置大块空间，容纳nobjs个大小为size的区块，如果无法达到nobjs个，会降低
    static char * chunk_alloc(size_t size, int & nobjs);
    
    // Chunk allocation state
    static char * start_free; // 内存池开始位置
    static char * end_free; // 内存池结束位置
    static size_t heap_size;
public:
    static void * allocate(size_t n) {...}
    static void deallocate(void * p, size_t n) {...}
    static void * reallocate(void * p, size_t old_sz, size_t new_sz);
};

// 静态成员变量的定义和设置初值
template <bool threads, int inst>
char * __default_alloc_template<therads, inst>::start_free = 0;
template <bool threads, int inst>
char * __default_alloc_template<therads, inst>::end_free = 0;
template <bool threads, int inst>
char * __default_alloc_template<therads, inst>::heap_size = 0;
template <bool threads, int inst>
__default_alloc_template<threads, inst>::obj * volatile __default_alloc_template<threads, inst>::free_list[__NFREELISTS] = {0, 0, 0, 0, 0, 0, 0, 0, 00, 0, 0, 0, 0, 0, 0, 0, };
```

### 空间配置函数

此函数首先判断区块大小，大于128bytes就调用第一级配置器，小于128bytes就检查对应的空闲链表，**如果空闲链表之内有可用的区块，直接使用，如果没有就将区块大小上调至8倍数，然后调用`refill()`，准备为空闲链表重新填充空间**

```c++
static void * allocate(size_t n) {
    obj * volatile * my_free_list;
    obj * result;
    // 大于128bytes
    if (n > (size_t) __MAX_BYTES) {
        return (malloc_alloc::allocate(n));
    }
    // 寻找16个空闲链表中适当的一个
    my_free_list = free_list + FREELIST_INDEX(n);
    result = * my_free_list;
    if (result == 0) {
        // 没有找到可用的空闲链表
        void * r = refill(ROUND_UP(n));
        return r;
    }
    // 调整空闲链表
    * my_free_list = result->free_list_link;
    return (result);
}
```

### 空间释放函数

此函数首先判断区块大小，大于128byte就调用第一级配置器，小于128bytes就找出对应的空闲链表，将区块回收

```c++
static void deallocate(void * p, size_t n) {
    obj * q = (obj *)p;
    obj * volatile * my_free_list;
    // 大于128bytes
    if (n > (size_t)__MAX_BYTES) {
        malloc_alloc::deallocate(p, n);
        return ;
    }
    // 找到对应的空闲链表
    my_free_list = free_list + FREELIST_INDEX(n);
    // 调整空闲链表
    q->free_list_link = * my_free_list;
    * my_free_list = q;
}
```

### 重新填充空闲链表

调用`refill()`可以为空闲链表准备重新填充空间，**新的空间将取自内存池（经由`chunk_alloc()`完成）**，默认取得20个新节点，但是如果内存池空间不足，可能会少于20

```c++
// 返回一个大小为n的对象，并且会适当给空闲链表增加节点
template <bool threads, int inst>
void * __default_alloc_template<threads, inst>::refill(size_t n) {
    int nobjs = 20;
    // 调用chunk_alloc()，尝试获取nobjs个区块作为空闲链表的新节点
   	char * chunk = chunk_alloc(n, nobjs);
    obj * volatile * my_free_list;
    obj * result;
    obj * current_obj, * next_obj;
    int i;
    // 如果只获得一个区块，这个区块就分配给调用者，空闲链表无新节点
    if (1 == nobjs) {
        return (chunk);
    }
    // 否则准备调整空闲链表，纳入新节点
    my_free_list = free_list + FREELIST_INDEX(n);
    // 在chunk空间创建空闲链表
    // 将这块返回给用户
    result = (obj *)chunk;
    // 引导空闲链表指向新配置得空间
    *my_free_list = next_obj = (obj *)(chunk + n);
    // 将空闲链表得各节点串接起来
    for (int i = 1; ; ++i) {
        current_obj = next_obj;
        next_obj = (obj *)((char *)next_obj + n);
        if (nobjs - 1 == i) {
            current_obj->free_list_link = 0;
            break;
        } else {
            current_obj->free_list_link = next_obj;
        }
    }
    return (result);
}
```

### 内存池

通过`chunk_alloc()`方法从内存池中读取空间给空闲链表使用

```C++
template <bool threads, int inst>
char * __default_alloc_template<threads, inst>::chunk_alloc(size_t size, int & nobjs) {
    char * result;
    size_t total_bytes = size * nobjs;
    size_t bytes_left = end_free - start_free; // 内存池剩余空间
    if (bytes_left >= total_bytes) {
        // 内存池剩余空间完全满足需求量
        result = start_free;
        start_free += total_bytes;
        return (result);
    } else if (bytes_left >= size) {
        // 内存池剩余空间不能完全满足需求量，但是能够供应一个以上得区块
        nobjs = bytes_left / size;
        total_bytes = size * nobjs;
        result = start_free;
        star_free += total_bytes;
        return (result);
    } else {
        // 内存池剩余空间连一个区块的大小都无法提供
        size_t bytes_to_get = 2 * total_bytes + ROUND_UP(heap_size >> 4);
        // 尝试利用内存池中的残余零头
        if (bytes_left > 0) {
            // 让内存池中的零头，先分配给适当的空闲链表
            // 首先寻找适当的空闲链表
            obj * volatile * my_free_list = free_list + FREELIST_INDEX(bytes_left);
            // 调整空闲链表，将内存池中的参数空间编入
            ((obj *)start_free)->free_list_link = *my_free_list;
            *my_free_list = (obj *)start_free;
        }
        // 配置heap空间，用来补充内存池
        start_free= （char *)malloc(bytes_to_get);
        if (0 == start_free) {
            // heap空间不足，malloc失败
            int i;
            obj * volatile * my_free_list, *p;
            // 尝试检索空闲链表中的内容，不会尝试配置较小的区块，因为这样会在多进程机器上容易导致灾难，所谓适当是指尚有未用区块，且却快足够大
            for (i = size; i <= __MAX_BYTES; i += __ALIGN) {
                my_free_list = free_list + FREELIST_INDEX(i);
                p = *my_free_list;
                if (0 != p) {
                    // 空闲列表内尚有未用区域
                   	// 调整空闲列表以释放未用区域
                    *my_free_list = p->free_list_link;
                    start_free = (char *)p;
                    end_free = start_free + i;
                    // 递归调用自己，修正nobjs值
                    return (chunk_alloc(size, nobjs));
                }
            }
            end_free = 0; // 完全没有内存
            // 调用第一级配置器，尝试使用OOM机制解决
            start_free = (char *)malloc_alloc::allocate(bytes_to_get);
            // 这样会抛出异常或内存不足的情况被解决
        }
        heap_size += bytes_to_get;
        end_free = start_free + bytes_to_get;
        // 递归修改nobjs
        return (chunk_alloc(size, nobjs));
    }
}
```

## 内存基本处理工具

STL定义五个全局函数，作用于未初始化空间上，用于构造的`construct()`和用于析构的`destroy()`，还有三个是，`uninitialized_copy()`，`uninitialized_fill()`，`uninitialized_fill_n()`分别对应高层次的`copy()`，`fill()`和`fill_n()`，SGI将它们定义于`<stl_uninitialized>`中

### uninitialized_copy

```c++
template <class InputIterator, class ForwardIterator>
ForwardIterator uninitialized_copy(InputIterator first, InputIterator last, ForwardIterator result);
```

**用于将内存的配置于对象的构造行为分离开**

如果作为输出目的地的`[reuslt, reuslt + (last - first))`范围内的每一个迭代器都指向未初始化区域，则`uninitalized_copy()`会使用`copy constructor`，给身为输入源的`[first, last)`范围内的每一个对象产生一个复制品，放进输出范围中

容器的全区间构造函数（range constructor）通常可以利用这个方法，两个步骤完成

* 配置内存区块，足以包含范围内的所有元素
* 使用`uninitialized_copy()`，在该内存区块中构造元素

这个函数接受三个参数

* 迭代器`first`指向输入端的起始位置
* 迭代器`last`指向输入端的结束位置
* 迭代器`result`指向输出短的起始位置

```c++
template <class InputIterator, class ForwardIterator>
inline ForwardIterator uninitialized_copy(InputIterator first, InputIterator last, ForwardIterator result) {
```

### uninitialized_fill

```C++

void uninitialized_fil(ForwardIterator first, ForwardIterator last, const T & x);
```

**用于将内存配置与对象的构造行为区分开**

如果`[first, last)`范围内的每个地带其都指向未初始化的内存，那么`uninitialized_fill()`会在该范围内产生x的复制品

这个函数接受三个参数

* 迭代器`first`指向欲初始化空间的起始处
* 迭代器`last`指向输出端的结束处
* x表示初值


### uninitiated_fill_n

```c++
template <class ForwardIterator, class Size, class T>
ForwardIterator uninitialized_fill_n(ForwardIterator first, Size n, const T & x);
```

**用于将内存配置与对象构造行为分离开**

它会为指定范围内的所有元素设定相同的初值，如果`[first, first + n)`范围内的每一个迭代器都指向未初始化的内存，那么`uninitialized_fill_n()`会调用`copy constructor`，在该范围生成x的复制品

这个函数接受三个参数

* 迭代器`first`指向欲初始化空间的起始处
* n表示欲初始化空间的大小
* x表示初值

```c++
template <class ForwardIterator, class Size, class T>
inline ForwardIterator uninitialized_fill_n(ForwardIterator first, Size n, const T & x) {
    return __uninitialized_fill_n(first, n, x, value_type(first));
}
```

首先萃取出迭代器`first`的value type，然后判断该类别是否为**POD类别**

```c++
template <class ForwardIterator, class Size, class T, class T1>
inline ForwardIterator __uninitialized_fill_n(ForwardIterator first, Size n, const T & x, T1 *) {
    typedef typename __type_traits<T>::is_POD_type is_POD;
    return __uninitialized_fill_n_aux(first, n, x, is_POD());
}
```

> POD是指Plain Old Data，也就是标量型别或传统的C struct型别，POD型别必须拥有trivial ctor/dtor/copy/assignment函数

因此对POD型别应该蔡邕最有效率的处置填写手法，而对non-POD型别蔡邕最保险安全的做法

```C++
// 如果是PDO类别，执行流程就会转进到以下函数，这是藉由function template的参数推导机制实现的
template <class ForwardIterator, class Size, class T>
ForwardIterator __uninitialized_fill_n_aux(ForwardIterator first, Size n, const T & x, __true_type) {
    return fill_n(first, n, x); // 交由高阶函数执行
}
// 如果不是POD类型，执行流程就会转进到以下函数
template <calss ForwardIterator, class Size, class T>
ForwardIterator __uninitialized_fill_n_aux(ForwardIterator first, Size n, const T & x, __false_type) {
    ForwardIterator cur = first;
    // 省略了异常处理
    for ( ; n > 0; --n, ++cur) {
        construct(&*cur, x);
    }
    return cur;
}
```
