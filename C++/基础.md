# 基础

## const

### const替换宏定义

对于单纯常量，使用`const`对象或`enum`替换`#define`

对于类似函数的宏定义，使用`inline`函数替换`#define`

### const修饰指针

* `const char * p`：表示指针指示的内容声明为`const`
* `char * const p`：表示指针本身被声明为`const`

### const修饰函数

* `const A test()`：声明函数的返回值为常量

* `A test(A a) const`：修饰函数，表示函数中不允许修改当前对象

  > 使用`mutable`修饰变量，表示这个变量是可变的，**这样这个变量被允许在const修饰的函数中被修改**

### 避免const和non-const成员函数代码重复

可以让`non-const`的成员函数中调用`const`的成员函数

但是如果在`non-const`的成员函数中直接调用，会导致`non-const`函数递归调用自己

通过使用类型转换操作避免发生这种问题

```c++
class Test {
public:
    ...
    const char & operator[](size_t position) const {
        ...
        return text[position];
    }
    char & operator[](size_t position) {
        return const_cast<char &>(
        	static_cast<const TextBlock&>(*this)[position]
        )
    }
}
```

## 初始化

**在使用对象前进行初始化**

对于大多数类型，相比调用默认构造函数然后调用赋值操作符，**只调用复制构造函数**更高效

**总是在初值列中列出所有成员变量**

## 构造/析构/赋值

### 默认生成

C++默认为类生成**复制构造函数**，**赋值运算符重写**和**析构函数**

这个默认的析构函数不是`virtual`声明的

对于含有不能进行赋值操作变量（内含references成员、内含const成员）的类进行赋值操作时，C++的响应是**拒绝编译那一行赋值动作**

### 拒绝默认生成

如果不需要编译器提供的默认函数，应该将其声明为私有

```c++
class A {
private:
    A(const A &);
    A & operator=(const A &);
};
```

A类可以作为接口类，**后续类可以通过继承A**，限制禁止默认复制和赋值的使用

```c++
class B : private A {
    ...
}
```

虽然编译器会自动给B生成默认函数，但是B调用时会因为无法调用父类的函数，导致调用失败

### 多态析构声明

在多态中，应该使用`virtual`修饰析构函数

实现`vitual`函数，对象必须携带信息，信息通常由一个vptr（virtual table pointer）指针指出，vptr指向一个由函数指针构成的数组，成为vtbl（virtual table），**实际调用函数取决于该对象的vptr所指出的vtbl**

也就是说，如果类中含有`virtual`函数，**其对象的体积会增加**，所以说在没有多态需求的类中，实现虚析构函数也是错误的

**不应该继承没有提供虚析构函数的类**

### 避免析构抛出异常

如果选择在析构函数中抛出错误，如果两个析构函数同时抛出错误，在程序不停止运行的情况下，可能会意想不到的结果，所以在开发过程中应该**避免在析构函数中抛出异常**

* **如果析构函数抛出异常就结束程序**，通常通过`abort`函数完成

* **捕获因调用`close`而发生的异常**

  ```c++
  A:~A() {
      try {
          ... // 异常
      } catch (...) {
          ... // 记录日志
      }
  }
  ```

  因为直接捕获异常，**可能会导致后续出现更严重异常**

* **提供普通函数执行析构操作**，如果用户需要对某个操作函数运行期间抛出的异常进行反应，那么类应该提供一个普通函数执行该操作

### 构造/析构中禁止调用虚函数

构造或析构都会优先调用基类的相应函数，如果在构造或析构中声明了虚函数，**在基类构造或析构过程中，虚函数不是虚函数，不会根据对象的类型调用**，而是直接调用基类的方法，可能会导致程序出现问题

### 在赋值运算符重载中处理“自我赋值”

```c++
A & A::operator=(const A & a) {
    delete pa;
    pa = new A(a.pa);
    return *this;
}
```

如果是上述情况，如果是自己调用自己的赋值运算符，那么在执行`delete pa`时，**也就已经将a中的数据清除**

```c++
A & A::operator=(const A & a) {
    if (this == &a) {
        return *this;
    }
    delete pa;
    pa = new A(a.pa);
    return *this;
}
```

可以像上述代码一样进行一个证同测试，或者可以像下述代码一样，在编写代码时，让`operator=`具备**异常安全性**

```c++
A & A::operator=(const A & a) {
    int * temp = pa;
   	pa = new int(a.pa);
    delete temp;
    return *this;
}
```

还可以使用**copy and swap**，类似于将引用传递修改为值传递

```c++
class A {
    void swap(A & a);
    A & A::operator=(const A & a) {
        A temp(a);
        swap(temp);
        return *this;
    }
}
```

### 复制时考虑所有成员

* **复制所有本地的成员变量**
* **调用所有基类内适当的复制函数**

## 设计与声明

### 使用外覆类型处理数据

```c++
struct Day {
    explicit Day(int d) : val(d) {};
    int val;
};
...
class Date {
public:
    Date(const Day & d, const Month & m, const Year & y);
    ...
};
```

**使用外覆类型时应该尽量使用`explicit`修饰构造函数，避免隐式类型转换**

在工程开发中，应该尽量选择使用`class`来代替`struct`

### 设计类需要考虑的问题

* **新类型的对象应该怎么被创建和销毁**

  这个问题包含了，构造函数和析构函数以及内存分配函数和释放函数的设计

* **对象的初始化和对象的赋值的区别**

  这个问题需要考虑，构造函数和赋值操作符的行为，以及两者的差异

* **新类型的对象值传递的问题**

  复制构造函数需要被考虑，当存在值传递的情况时

* **新类型的合法值**

  通常新类型只有某些数据集是有效的，这需要对class进行维护和约束条件，以及对成员函数的错误检查和异常管理

* **新类型的继承关系**

  需要考虑`virtual`和`non-virtual`的影响，以及希望被其他类继承，需要考虑析构函数以及其他函数是否需要被`virtual`修饰

* **新类型的类型转换问题**

  需要考虑这个类型需要和那些类型进行转换，如果不希望存在隐式转换，是否需要使用`explicit`进行修饰

* **新类型的函数和操作符重载**

  根据需求考虑需要重载什么操作符以及需要设置那些成员函数

* **新类型的未声明接口**

  需要考虑效率、异常安全性以及资源运行等方面的保证，通过私有的成员函数去控制

* **新类型模板**

  考虑新类型的一般化，如果存在类型家族，那么可以考虑创建一个模板类

* **新类型的必要性**

  是否可以通过，定义一个或多个非成员函数或者模板方法，就能够实现类的功能，或者是通过继承就能够达到所需的标准

### 使用常量引用传递替换值传递

默认情况下C++都是通过值传递的方式传递对象，函数参数都是以实际实参的复件为初值，而调用端所获得的亦是函数返回值的一个复件

通过**使用常量引用传递**的方式，没有任何构造函数和析构函数将会被调用，如果在函数中需要修改这个对象，那么可以使用引用传递

通过引用传递的方式，还可以**避免对象切割问题**，当一个派生类对象通过值传递的方式传递并被视为一个基类对象时，基类对象的复制构造函数就会被调用，这样就会产生对象切割问题

在C++编译器底层，引用往往通过指针实现出来，**因此引用传递通常意味真正传递的是指针**，因此如果对象属于是**内置类型**，那么使用值传递效率会高于引用传递，**但这种情况需要根据编译器做考虑，通常情况内置类型、STL的迭代器和函数对象还是选择值传递**

### 返回值返回对象和引用

绝对不要返回指针或者引用指向一个临时变量，或者返回一个指向堆内存的对象，或者返回会指针

### 使用非成员非友元函数替换成员函数

**越多的函数可以访问数据，数据的封装性就越低**

成员变量是被存放在`private`中，能够访问`private`成员变量的只有类成员函数和友元函数

### 不抛出异常的swap函数

缺省时标准库中自带的swap函数的实现

```c++
Template<typename T>
void swap(T & a, T & b) {
    
    T temp = a;
    a = b;
    b = temp;
}
```

自带的swap函数，核心在于三次复制，如果对象很大，效率就会极其低下

```c++
class Widget {
public:
    void swap(Widget& other) noexcept {
        std::swap(pImpl, other.pImpl);
    }
private:
    WidgetImpl* pImpl;
};
```

通过自定义swap函数，修改为通过指针交换，就能够提高效率

**在swap函数中，不应该抛出异常**

因为很多异常安全技术依赖于`swap`，例如避免自我赋值的**copy-and-swap**

```c++
Widget& operator=(Widget rhs) {
    swap(rhs);
    return *this;
}
```

如果swap抛出异常，可能导致对象处于半修改状态

所以应该使用`noexcept`修饰`swap`方法

并且最好能够提供一个成员`swap`一个非成员`swap`，因为**很多的STL算法会调用`swap(a, b)`**

在使用`swap`时应该选择写成

```c++
using std::swap;
swap(a, b);

std::swap(a, b); // 会优先使用标准库自带的
```
