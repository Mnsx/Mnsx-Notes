# 类的实现

## 延后变量定义的出现

尝试延后变量的定义，直到非得使用该变量位置，甚至应该延后定义到**能够给他赋初值参数为止**

* **定义在循环外**

  ```c++
  A a;
  for (int i = 0; i < n; ++i) {
      a // 赋值操作
  }
  ```

  这种写法的成本在于：1个构造函数 + 1个析构函数 + n个赋值操作

* **定义在循环内**

  ```c++
  for (int i = 0; i < n; ++i) {
      A a;
  }
  ```

  这种写法的成本在于：n个构造函数 + n个析构函数

**如果n的值很大的情况下，做法A会高效很多，否则还是做法B会更好**

## 减少转型

C风格的转型动作

* `(T) expression`
* `T(expression)`

两种形式并无差别，这两种方式被称为**旧式转型**

C++提供四种新式转型

* `const_cast<T>(expression)`通常被用来将对象的常量性转移
* `dynamic_cast<T>(expression)`主要用来执行**安全向下转型**，唯一无法由旧式语法执行的动作，也是唯一**可能耗费重大运行成本的转型动作**
* `reinterpret_cast<T>(expression)`意图执行低级转型，实际动作（及结果）可能取决于编译器，这也就表明它不可移植
* `static_cast<T>(expression)`强迫隐式转换

更推荐使用新式转换，第一，代码可读性，第二，各转型动作的目标越窄化，编译器越可能诊断出错误的运用

```c++
class A {
public:
    virtual void a() { ... }
};
class B : public A {
public:
    virtual void a() {
        static_cast<A>(*this).a(); // 可能出现错误
    }
}
```

上述代码中，`static_cast<A>(*this).a()`**调用的是转型过程副本对象上调用的a方法**，如果a方法修改了对象内容，当前对象其实没有改动，改动的是副本

**`dynamic_cast`的许多实现版本执行速度相当慢**

有两种方法可以避免使用`dynamic_cast`

1. **使用容器**并且在其中存储直接指向`derived class`对象的指针，这样便消除了通过`base class`接口处理对象的需要
2. 在`base class`内提供`virtual`函数对派生类进行操作

## 异常安全性

异常安全码必须提供下述三种保证之一

* **基本型**

  如果异常被抛出，程序内的任何事物仍然保持在有效状态下，没有任何对象或数据结构会因此而败坏，所有对象都处于一种内部前后一致的状态

* **强烈型**

  如果异常被抛出，程序状态不改变。如果调用函数抛出异常，程序会回复到调用函数前的状态

* **不抛异常型**

  绝不抛出异常

**一般情况下应该考虑提供第二种保证**，实在无法保证也应该让函数拥有基本承诺

**copy and swap**为打算修改的对象做出一份副本，然后再副本身上做一切必要修改，**如果任何修改动作抛出异常，元对象仍保持未改变状态**

但是存在**连带影响**和**效率**两个因素会阻止使用**copy and swap**进行异常安全操作

## inline函数

`inline`函数在减少函数调度的开销的同时，也需要以函数本体替换函数的调用，这会使目标码大小增加，**这会导致额外的换页操作，降低指令高速缓存装置的集中率**

`inline`和`templates`两者通常都被定义在头文件中，**但是这可能是无效并且有害的**

`inline`函数通常被置于头文件内，因为大多数编译环境，在编译过程中进行`inlining`操作，而为了将一个函数调用替换为被调用函数的本体，编译器需要知道函数的具体实现

`templates`通常被置于头文件内，因为它一旦被使用，编译器为了将它具现化，需要知道代码的具体实现

**`virtual`会使得`inline`失效**，因为`virtual`是在运行期才告诉代码调用那个函数，而`inline`需要在编译期将代码调用替换为代码

大多数编译器提供了一个判断级别：**如果它无法将要求的函数`inline`，会给一个警告信息

## 降低文件编译依存关系

C++的`#include`是文本替换，头文件互相包括会形成**强编译依赖**，只有一个头文件被修改，所有直接/间接包含它的文件都要重新编译

* **能使用指针/引用，就不用对象**

  声明指针/引用**只需要前置声明**，不需要包含完整定义，而定义对象，**必须包含类的完整定义**

  ```c++
  class string;
  string * a; // 这是被允许的
  void fun (string & a); // 这也是被允许的
  ```

* **尽量用前置声明替换`#include`**

  **函数声明、参数/返回值为指针/引用时，只需要前置声明**

* **用句柄类（Handle）或接口类（interface）解耦**

  * **Handle类**，头文件只暴露指针，实现细节放在源文件中

    ```c++
    // A.h
    class AImpl;
    
    class A {
    private:
        AImpl * aImpl;
    public:
        // 对外接口
        ...
    };
    ```

    ```c++
    // A.cpp
    #include "A.h"
    
    class AImpl {
    	... // 代码实现
    }
    ```

  * **interface类**，用抽象基类做接口，派生类做实现，客户端只依赖接口，不依赖具体实现

    ```c++
    // IA.h
    class IA {
    public:
        virtual ~IA() = default;
        virtual void getInfo() = 0;
    };
    ```

    ```c++
    // A.h
    class A : public IA {
    public:
        void getInfo() override;
    };
    ```

    ```c++
    // A.cpp
    void getInfo() {
        ...
    }
    ```
