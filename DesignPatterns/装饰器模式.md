# 装饰器模式

Decorator就是在不修改原类的情况下，动态的给对象增加功能

## 需要装饰器模式的原因

```c++
class Coffee {
public:
    virtual double cost() {
        return 10;
    }
};
```

需要需要给这个类添加功能，加牛奶、加糖、加巧克力...

如果使用继承实现，那么这个类会爆炸增长

## 简易实现

### Component

```c++
class Coffee {
public:
    virtual double cost() = 0;
    virtual ~Coffee() = default;
};
```

### ConcreteComponent

```c++
class BasicCoffee : public Coffee {
public:
    double cost() override {
        return 10;
    }
};
```

### Decorator

```c++
class CoffeeeDecorator : public Coffee {
protected:
    Coffee * coffee;
public:
    CoffeeDecorator(Coffee * c) : coffee(c) {}
    double cost() override {
        return coffee->cost();
    }
};
```

### ConcreteDecorator

* Milk

  ```c++
  class MilkDecorator : public CoffeeDecorator {
  public:
      MilkDecorator(Coffee * c) : coffeeDecorator(c) {}
      double cost() override {
          return coffee->cost() + 2;
      }
  }
  ```

* sugar

  ```c++
  class SugarDecorator : public CoffeeDecorator {
  public:
      SugarDecorator(Coffee * c) : CoffeeDecorator(c) {}
      double cost() override {
          return coffee->cost() + 1;
      }
  }
  ```

## 装饰器模式和代理模式的区别

* **Decorator：增加功能**	`对象 = 原对象 + 新功能`
* **Proxy：控制访问**               `对象 = 原对象 但访问需要通过代理` 

| 特性           | Decorator  | Proxy      |
| -------------- | ---------- | ---------- |
| 目的           | 增加功能   | 控制访问   |
| 是否改变行为   | 会增强行为 | 不改变行为 |
| 是否可以叠加   | 可以多层   | 通常一层   |
| 客户端是否感知 | 通常不关心 | 可能关心   |
