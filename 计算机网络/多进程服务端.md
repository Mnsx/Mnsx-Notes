# 多进程服务端

## 进程概念

### 并发服务器的实现方法

网络程序中数据通信的事件比 CPU 运算时间占比更大，向多个客户端提供服务是一个有效利用 CPU 的方式

* **多进程服务**：通过创建多个进程提供服务
* **多路复用服务器**：通过绑定并同一管理 I/O 对象提供服务
* **多线程服务器**：通过生成与客户端等量的线程提供服务

### 进程

进程的定义是——占用内存空间的正在运行的程序

无论进程是如何创建的，所有进程都会从操作系统分配到 ID 被称为进程 ID ，其值为大于2的整数，因为1要分配给操作系统启动后的首个进程（用于协助操作系统），因为用户进程无法得到 ID 值1

### 僵尸进程

进程完成工作后应被销毁，但有时这些进程会变成僵尸进程，占用系统中的资源

向exit函数传递的参数值和main函数的return语句返回的值都会传递给操作系统，而操作系统不会销毁子进程，直到把这些值传递给产生在子进程的父进程。处于这种状态下的进程就是僵尸进程

可以让父进程等待子进程结束工作并销毁，防止僵尸进程

## 信号处理

### 信号

信号是软件中断，当特定事件发生时，内核会打断正在执行的代码，强迫进程去执行一个预先定义好的函数

### 核心函数

sigaction函数是POSIX标准，用于检查或修改与指定信号相关联的处理动作

```c++
#include <signal.h>
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
```

* `signum`：要操作的信号编号
* `act`：指向struct sigaction结构体指针，用于设置新的信号处理方式，如果为NULL，表示只检查当前处理方式
* `oldact`：指向struct sigaction结构体指针，用于保存该信号之前的处理方式，如果为NULL，则不保存

```c++
struct sigaction {
    void (*sa_handler)(int);                // 信号处理函数指针（老式用法）
    void (*sa_sigaction)(int, siginfo_t *, void *); // 信号处理函数指针（新式用法，带详细信息）
    sigset_t sa_mask;                       // 信号处理函数执行期间需要阻塞的信号集 [1]
    int sa_flags;                           // 标志位，用于控制信号的行为（如 SA_SIGINFO） [1]
    void (*sa_restorer)(void);              // 已废弃，通常不使用
};
```

### 核心信号

* **SIGCHLD**

  子进程结束时会变成僵尸进程，在信号回调时调用`waitpid()`杀死僵尸进程

* **SIGPIPE**

  当客户端异常关闭了连接，如果尝试向这个断开的Socket写入数据，内核会发送SIGPIPE

  默认的处理方式是，直接杀掉进程

  在服务器启动时，应该显示的忽略它，`signal(SIGPIPE, SIG_IGN)`，这样写入失败只会返回错误码

* **SIGINT / SIGTERM**

  当用户按下ctrl+c时发送

  不应该让进程暴力的退出，在信号处理函数中设置一个全局标志位，让程序收到信号后，安全的退出
