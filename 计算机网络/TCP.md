# TCP

## TCP/IP 协议栈

TCP/IP协议栈主要分为4层，应用层 -> TCP层/UDP层 -> IP层 -> 链路层

* **链路层**

  链路层是物理链接领域标准化的结果，专门定义LAN、WAN、MAN等网络标准

* **IP层**

  为了在复杂的网络中传输数据，需要考虑路径的选择，解决这个问题就是IP层

  IP本身是面向消息的不可靠协议，每次传输数据时会选择路径，并且不相同，如果路径错误，则选择其他路径，但是如果数据丢失或错误，则无法解决

* **TCP/UDP层**

  TCP和UDP层以IP层提供的路径信息为基础完成实际的数据传输，所以又叫做传输层

  TCP可以保证可靠的数据传输

* **应用层**

  上述内容时套接字通信过程中自动处理的，选择数据传输方式、数据确认过程都被隐藏到套接字内部

  根据程序特点决定服务端和客户端端之间的数据传输规则，这就是应用层协议

## TCP原理

### I/O缓冲

**TCP套接字的数据收发无边界**，如果服务端调用传输40字节的数据，客户端可能通过4次接收数据，每次接收10字节，过程中字节会存储在I/O缓冲区中

调用write时，数据将移到输出缓冲，在适当的时候传向对方的输入缓冲

* I/O缓冲在每个TCP套接字中单独存在
* I/O缓冲在创建套接字时自动生成
* 即使关闭套接字也会继续传递输出缓冲中的遗留数据
* 关闭套接字将丢失输入缓冲中的数据

TCP中有滑动窗口协议，所以不会出现超过输入缓冲大小的数据传输

### 主机连接原理

TCP套接字从创建到消失所经过程

* 与对方套接字建立连接
* 与对方套接字进行数据交换
* 断开与对方套接字的连接

TCP在实际通信过程中称为三次握手，套接字是以全双工方式工作，可以双向传递数据

1. 请求连接的主机A向主机B发送信息

   ```shell
   [SYN] SEQ: 1000, ACK: -
   ```

   上述SEQ为1000， ACK为空

   SEQ代表现在传递的数据包序号为1000

   这是首次请求连接时使用消息，称为`SYN`（Synchronization），表示收发数据前传输的同步信息

2. 主机B向主机A发送消息

   ```shell
   [SYN+ACK] SEQ: 2000, ACK: 1001
   ```

   此时SEQ为2000， ACK为1001

   对主机A首次传输的数据包确认消息和为主机B传输数据做准备的同步消息绑定发送，所以此类型消息称为`SYN+ACK`

   **收发数据前向数据包分配序号，并向对方通报此序列号，这都是为了防止数据丢失做准备**

3. 主机A向主机B传输消息

   ```shell
   [ACK] SEQ: 1001, ACK: 2001
   ```

   这是表示已经接收到SEQ=2000的数据包，可以接收2001的数据包了，并且发送2001数据包

### 数据交换原理

数据发送过程中ACK号的增量为传递的数据字节数，即ACK号 -> SEQ号 + 传递的字节数 + 1

在传输过程中如果出现数据包丢失的情况，那么主机B就无法发送ACK信号，所以主机A就会尝试重传此数据包，并且为了完成数据包重传，**TCP套接字启动计时器以等待ACK应答，如果计时器超时则会进行重传**

### 断开连接原理

数据包中FIN表示断开连接，双方会各自发送一次FIN消息然后断开连接，此过程分为4阶段，被称为四次挥手
